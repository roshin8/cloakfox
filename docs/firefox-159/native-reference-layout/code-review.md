## Finding

### P2 — Canonical geometry still admits host-dependent UA platform styling

Changed-code anchor: `patches/cloakfox-canonical-layout-geometry.patch:557–562`, the new fixed canonical scrollbar theme. Related admission: the same patch's `CaptureCloakfoxCanonicalLayout` and `CloakfoxCanonicalGeometryReady` additions.

The fixed theme does not remove the actual host platform from UA style computation. `firefox-src/layout/style/res/forms.css:299–301` applies `scrollbar-width: thin` to `select:-moz-select-list-box` only when `(-moz-platform: macos)` matches. `Gecko_MediaFeatures_MatchesPlatform` in `firefox-src/layout/style/nsMediaFeatures.cpp:318–339` still selects the compilation platform, while the Rust caller ignores its document context. The new theme deliberately honors `scrollbar-width`, so `ConfigureScrollbarSize(17)` produces an 8-pixel thin scrollbar on macOS and a 17-pixel automatic scrollbar elsewhere. `nsListControlFrame::IntrinsicISize` explicitly adds these scrollbar sizes (`firefox-src/layout/forms/nsListControlFrame.cpp:131–144`). An ordinary intrinsically sized `<select size="2">` or multiple select therefore retains host-dependent geometry after the document has been admitted and geometry presentation protection is removed.

There is a second affected UA branch: `firefox-src/layout/style/res/html.css:973–980` enables `font-variant-east-asian: ruby` on non-Windows hosts. An author font with ruby alternate glyphs can consequently shape differently on different hosts despite using identical font bytes and the same canonical profile.

Bounded repair: make the privileged platform media evaluation document-aware and choose one fixed platform for documents whose immutable `CloakfoxCanonicalLayout()` flag is set, including normalized external resource documents. Preserve the existing platform result for ordinary and chrome documents. Alternatively normalize every affected UA rule with equivalent per-document scoping. Keep author `scrollbar-width` choices functional. Add a listbox and ruby-font case; the current geometry fixture contains a single-selection combobox, which does not exercise the listbox branch. The remaining Android branches found in `forms.css`, `scrollbars.css`, and `accessiblecaret.css` are further reasons to normalize the UA platform decision consistently instead of changing only one listbox rule.

### P2 — Full canonical composition clip still starts inside a left scrollbar

Anchor: `patches/cloakfox-canonical-layout-geometry.patch:545–550`, corresponding to `firefox-src/layout/generic/ScrollContainerFrame.cpp:4072–4080`.

The new path moves classic root scrollbars inside the async zoom container and expands that container's clip to the full composition size, but only changes the clip's size. Its origin still comes from `effectiveScrollPort`, which is `mScrollPort` on desktop. With a left root scrollbar (`layout.scrollbar.side=3`, or the default side policy with an RTL browser UI), `mScrollPort.x` is the scrollbar gutter width. `LayoutScrollbars` places that scrollbar at the outer frame's left edge instead. Consequently the new wrapper clip starts to the right of the scrollbar it now wraps, clipping its painting and hit testing. At non-unit output scale the retained layout-space gutter origin also disagrees with the physical composition size.

Use the full outer/composition origin as well as its full size for the canonical wrapper clip, while retaining the inset scrollport clip for the content. Either normalize the canonical root scrollbar side independently of host UI preferences or explicitly support and test both sides. Add a left-side/RTL control with widget pixels and native thumb interaction at 1x and 2x; current acceptance drag and right-edge assertions cover only a right-side root bar.

## Follow-up: physical viewport, scrollbar input, and fixed-element culling
